# Crates: core and ingest

Detail moved out of `CLAUDE.md`. Overview of all crates: `docs/ARCHITECTURE.md` §2.

- **retrodoc-core**: shared domain model (`Domain`/`Feature`/`UseCase`/`Step`/`ConfidenceScore`/`BusinessRule` (ADR 0021, filled by the `rules` pass)
  in `model.rs`), `retrodoc.toml`
  config (`config.rs`) and the text helpers every other crate shares (`text.rs`: `one_line`,
  which keeps a name or a description from forging a line of a prompt or a list; `fold_latin`, which lowercases and
  folds accented Latin letters to their base letters, for the slugs (DLG-5) and the tag of `[output] language` (DLG-9);
  `normalize`, the one comparison of names across passes; `thousands` and `format_duration`, the figures of the
  recap, the estimate and the audit page),
  the BM25 ranking the search, the reconciliation and the brief evidence share (`bm25.rs`, ADR 0053: `Bm25`,
  `tokenize`, `has_content_words`; lexical, rebuilt at each start, no persistence),
  the deterministic part of the reconciliation with the project's own docs (`reconcile/`, ADR 0053,
  `specs/docs-reconciliation.md`: the items, their matching with the doc sections, the saved verdicts `Judgements`
  applied with the values the file records (REC-17), `Reconciliation`), which `generate` and the readers share,
  the debt report and the domain models (`report/`, ADR 0053, `build_report`, `domain_models`, `DebtReport`):
  the documentation debt report from the saved artifacts (`retrodoc report`, no LLM; `mod.rs` builds it and writes `to_markdown` with the core sections; the optional sections are apart: the behaviours in `behaviour.rs`, the existing docs in `reconciliation.rs`, the rules set aside in `set_aside.rs`); the sections a human marked wrong (`marked_wrong`, filled from `reviews.json` by `GeneratedDocs::debt_report` of `retrodoc-mcp`, in the printed report and `coverage-report.md` alike) go to "Sections marked wrong" with the comment of the review (`specs/debt-view.md` DBT-35); the use cases whose narrative the confidence pass judged `unsupported` (`narrative_check` at 0: the shown code contradicts a claim; `partial` ones are not listed) go to the section "Narratives the cited code contradicts" with the model's reason (`specs/use-case-confidence.md` CNF-9); the domains no feature belongs to (`DomainMap::featureless`) go to "Domains with no feature", with the number of their features set aside (filled by `with_technical_features`; `specs/featureless-domains.md`); with a saved `BehaviourCoverage` it lists the entry points without a feature and the technical support; with a `Reconciliation` (`with_reconciliation`), the section "Existing documentation": per domain the items documented, matched but not judged, undocumented and contradicted, then the contradictions (both sides cited, a finding to check) and the undocumented items, most entry points first;
  the artifacts the readers of the docs load (`artifacts/`, ADR 0051: `Glossary` with `merged_entities`, `DomainMap`
  with the domains it publishes, `Scope`, what the budget left out, `BehaviourCoverage`, `SourceHashes`, `SetAside`, what the rules pass set aside,
  each with its `load` and `save`; `items.rs`: `load_features`, `load_technical_features`, `load_use_cases`,
  `load_rules` and the savers of the features, use cases and rules; `estimate.rs`: `RunEstimate`, the estimate of a
  `generate` as saved with its run, and how a measured figure stands against its range, `PassEstimate::against`),
  and the layout of `.retrodoc/cache/` the pipeline writes and the readers of the docs read (`cache/`, ADR 0051):
  `Artifact`, the names of everything under `.retrodoc/cache/` and which `generate --force` clears; `load_yaml`,
  `load_json` (a missing or unreadable file is a first run, `None`, not an error), `save_yaml`, `save_json` (written
  beside, synced, then renamed, `CacheError`); `hash_content`, the SHA-256 of the fingerprints and source hashes;
  `format` (`FORMAT_VERSION`, the format of the cache in `format.json`: `record` writes it when it says otherwise,
  `check` refuses an older, later or unreadable one, no file reading as format 1; `check` sees no cache in a `format.json` alone; `set_aside_older` moves every file of an older one but `history/` to `.retrodoc/cache-format-<found>/` for `generate --force`, the run history left in place; not part of the fingerprints, ADR
  0050, `specs/cache-format.md`).
- **retrodoc-ingest**: reads the target repo — the sections of the project's own docs the reconciliation matches
  (`doc_corpus::corpus`, REC-1, returning the `Section` of core); file walker respecting `.gitignore` (`walker.rs`; classifies files as `Source`/`Test`/`Markdown`/`Other` —
  the built-in extensions and test conventions cover the reference set of `specs/language-agnostic.md`, the
  build scripts `*.gradle.kts`, `Package.swift`, the view templates `*.blade.php`, `*.html.php`, `*.tpl.php` and the root `project/` of an sbt build excepted, even when the roles call names their extension; tests are detected by directory (.NET `*Tests` projects, and for .NET files `*.Test`, `*UnitTest`, `*IntegrationTest`, `*.Specs`; Gradle test source sets `src/<set>Test/<jvm language>/` and the Android variants `src/testDebug/`, `src/androidTestRelease/` included) or file-name convention and kept out
  of the pipeline, which only consumes `Source`), one-pass
  git history per file via `git2` revwalk+diff (`git_history.rs`, not a `git log` per file — matters for
  perf on large repos; `user_name` reads the `user.name` of the repo's git config, the author of a review; `file_log` is the exception, the recent commits of one file for the MCP `git_log`, across its renames: a whole-tree diff with rename detection only on the commits that add the tracked path; about 0.35 s for a full walk of 12k commits), existing Markdown docs (`existing_docs.rs`), and the signals of the product brief (`signals.rs`: `Signal` with a citable origin; doc sections cut at headings, root `*.md` included; commit subjects from `git_history::scan_history`, the same one revwalk as `collect_history`, without merges, bots and dependency bumps, `feat`/`fix` first in a Conventional Commits repo; manifest metadata (one root manifest per reference language of `specs/language-agnostic.md`, `*.csproj` under any name, plus the walked ones the root `.sln`/`.slnx` lists, else those one or two levels down, test projects left out, at most 20; Gradle and SBT scripts read by string scanning, Gradle with no project name, plus the libraries of the Gradle version catalog `gradle/libs.versions.toml`), the tree two levels deep, Gherkin `.feature` titles and test descriptions (`test_phrases`, shared with the glossary), schema tables, migration names and translated texts (one language), read by format (SQL DDL, `ActiveRecord` schema, YAML/JSON/properties/gettext) from the files a `SourceMap` selects (rules `kind + glob + format`; `SourceMap::sniff` guesses them from file content on any stack, no location is hard-coded; `retrodoc-pipeline`'s `sources` replaces it with an LLM-inferred, editable one); `signals::collect(repo_root, &ingest, &sources)` gathers them all, with `IngestResult.commits` coming from the same walk as the history; ADR 0019). `structure.rs` (ADR 0022) parses a source file with tree-sitter and returns its definitions (name, kind, line range, signature: the line declaring it, past its annotations) and references, for Ruby, Rust, JavaScript, TypeScript/TSX, Python, Java, Kotlin, Scala, C#, PHP, Go, C, C++ (headers `.h` included) and Swift (one cargo feature per language, all on by default, each setting the `grammar` feature; the grammars' `tags.scm` queries, completed where they miss calls or types, and written in `structure.rs` for Kotlin and Scala, whose crates export none, and for C, C++ and Swift, whose queries span a function over one line or its whole class; `None` for any other file, which keeps the lexical paths; `same_language` says whether a name one file defines is one another can call, by family: JavaScript with TypeScript, Java with Kotlin and Scala, C with C++); `retrodoc-pipeline`'s `Splitter` cuts those languages at the parsed definitions. `run()` combines the three into an
  `IngestResult`.
