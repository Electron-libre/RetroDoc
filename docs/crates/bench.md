# Crate: retrodoc-bench

The measuring tools, kept out of the passes ([ADR 0042](../adr/0042-the-measuring-tools-live-in-a-crate-of-their-own.md)):
`retrodoc benchmark` and `benchmark-table` call it, the examples of `examples/` are the replays and the measures of
`docs/dev/commands.md` (`cargo run -p retrodoc-bench --example <name>`). It reaches the private items of the passes
through the `bench` feature of `retrodoc-pipeline` (`bench_support`, `rules::bench`), absent from its default
build (the workspace build turns it on, so `just clippy` also lints that default build alone), and its tests
use the fake LLM of the `testing` feature. Its root names the modules of `retrodoc-pipeline`
as its own, so the files moved from that crate kept their `crate::<module>` paths.

| Module | Role |
|---|---|
| `benchmark/` | Quality benchmark (`issues/done/quality_benchmark.md`, `issues/done/benchmark_spread_and_judge_bias.md`): `Reference` (hand-written `benchmark/<repo>/reference.yaml`, checked on load) and `RunMetrics` (sizes, mean business-language score and the share of use cases at score 1, mean confidence, cost of the last `generate`, read from `.retrodoc/cache/`, no LLM). `Matches` (hand-written `matches.yaml`; a generated name may have several pairs, one per reference item it holds, added to the normalized-name match; its `rejected` pairs, the judge's proposals found wrong by hand, never count, and one also kept as a pair is an error) and `compare` (recall and precision of domains and features, a generated name counted once for precision, with what is left unmatched; spec `benchmark-scoring`). `judge` (LLM proposals pairing every generated item with the reference items left uncovered, several per generated item allowed, a name copied with its description read as that name, an answer with no pair asked once more and warned about, as are the dropped proposals, a kind still with no pair marked `unjudged` in `judge.yaml`, rating of narratives; adds to `matches.yaml`, never removes a pair of it; `Matches::unaudited` counts the proposals neither paired nor rejected by hand) and `summary` (the text `retrodoc benchmark` prints, an `unjudged` kind shown as unjudged, the unaudited proposals counted) and `table` (`RunReport` per run, stamped with `SCORING_VERSION`, series per configuration, mean/range/change table; no change of the recalls, precisions and judge's rating against a previous series scored under another or an unknown version, a note on a series of mixed versions; an `unjudged` kind has no judged recall and precision in its run and is counted under the series; the unaudited proposals of each kind, mean and range). `Judgement::load` reads a saved `judge.yaml` to re-score a run with no LLM call. `frozen` (`FrozenInputs`: the artifacts of one good run kept in `~/retrodoc-runs/frozen/<repo>/` with a `manifest.yaml` naming the model and commit; `prepare(ReplayPass, work_root)` copies them without the artifact of the replayed pass and the ones after it, so one pass runs alone on fixed inputs; `issues/done/benchmark_passes_on_fixed_inputs.md`). `replay` (`replay_domains` and `replay_features`: run the surface clustering, or the features pass on the frozen domains (`FrozenInputs::replace_domains` freezes domains clustered from the surface, the ones of the `files` path hold no resources), once on a work directory prepared from `FrozenInputs`, score the domains or the features against the reference strictly and with the pairs the judge proposes, counts the calls and tokens of the pass apart from the judge's; `replay_table`: one row per run, mean and range, a run whose kind is `unjudged` shown so in the judge columns, left out of their mean and range and counted under the table; `replay_use_cases` runs the use cases pass on the frozen features, reading the code of a copy of the tree, and measures the use cases, their grounding included (steps that cite code and that `mechanical_score` passes; `UseCaseFigures`, `use_case_table`); `replay_rules` does the same for the rules pass on frozen features and use cases, given the extracts `generate` gives that pass (the evidence of its `Frame`, as `rule_evidence`; empty to reproduce the rules baselines measured before 2026-10-31) and the put-backs `[rules]` of the source tree gives it (`tree_put_back`) (`RuleFigures`, `rule_table`: rules stated and kept, rules of the reference a generated rule states by the judge, which sees the 12 closest by BM25); `replay_judgement` asks again only the judgement per rule of the rules pass (`rules::bench::judge_rules_with`, the system prompt given, with or without the rules of other features on the same files added by the replay, never by the pass) on the rules a saved run stated, the statements fixed, and `score_labels` scores it on hand labels (good rules and noise dropped; `issues/done/rules_plumbing_and_screen_noise.md`, example `rules_judge_replay`); the `pass_replay` example runs a pass N times; every replay works from the frozen entry points without the routes `generate` leaves out, `EntryPoints::without_routes_declared_elsewhere`, but with the public API it would leave out; frozen features written before cite the routes left out, so freeze them again, `--freeze-first` on `features`, before a use cases replay). `frame` (`Frame`: the brief and evidence a features, use cases or rules replay is given, by default the frozen brief and no evidence (the `pass_replay` example gives the evidence by default, as `generate`); `tree_evidence` builds the extracts from the signals of the source tree, its generated docs left out, reading only its `[ingest]` and `[output]` (`Config::load_ingest_and_output`; `tree_put_back` reads only its `[rules]`, `Config::load_rules`) so a saved run of the removed `files` path still serves; `issues/done/brief_injection_experiments.md`). |
