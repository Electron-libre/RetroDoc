# Crate: retrodoc-llm

Detail moved out of `CLAUDE.md`. The LLM boundary: `docs/ARCHITECTURE.md` §8.

- **retrodoc-llm** (`types.rs`, `heartbeat.rs`, `openrouter/` with the provider in `mod.rs` and its tests by theme in `tests/`, `usage.rs`): `LlmProvider` trait abstraction (kept provider-agnostic) + `OpenRouterProvider`, which serves
  `provider = "openrouter"` and `"deepseek"` (same chat-completions format, own endpoint and key variable; ADR 0024), a real `reqwest` HTTP client with exponential-backoff retry on
  429/5xx that honors the delay the server asks for (`Retry-After`, Google's `retryDelay`; up to 120 s, a longer
  one is an error). Per-request HTTP timeout is 120 s, 900 s for a loopback `llm.base_url` (`localhost`, `127.0.0.0/8`, `::1`: a local
  model writing a long JSON answer needs it, LTO-1 to LTO-3), unless `llm.timeout_secs` is set (a timeout is not retried, the same prompt would take as long again: the error says so, gives the timeout that applied and names `llm.timeout_secs`). `CompletionRequest.json_schema` is the optional shape of a JSON answer, sent as a strict `response_format` (plus OpenRouter's `require_parameters` on its real endpoint) unless `llm.structured_output = false`; a 400/404/422 is sent again without it, and if that works the schema is left out for the rest of the run (ADR 0023). `llm.temperature` (also per pass) is sent as `temperature` when set, and unset it is 0 for the passes of `ZERO_TEMPERATURE_PASSES` (every pass but the benchmark judge, ADR 0031), outside the fingerprints; a 400/404/422 is sent again without it (schema kept), and if that works it is left out for the rest of the run. `CompletionRequest.tools` offers tools to the model (sent as `tools` of type `function`, none sent when empty), `CompletionResponse.tool_calls` holds the calls it asks for (id, name, arguments as the raw text the server sent, `{}` when `null`; a call without an id gets one of its own; a `null` content next to them is an empty text, with no call an invalid response; a `null` `tool_calls` is none), and `ChatMessage::assistant_calls` / `ChatMessage::tool_result` give the calls and their results back in the next request (ADR 0046, TCL-1 to TCL-14). A 400/404/422 to a request offering tools whose body says the tools or function calling are not supported and names neither the temperature nor the schema (Ollama "does not support tools", OpenRouter "no endpoints found that support tool use", "does not support Function Calling") is not sent again without the temperature or the schema: the error says at once that the model or its server refuses tools, with the model and the server's answer (TCL-15, TCL-16). The `reasoning_content` of a thinking model (DeepSeek) is kept as `CompletionResponse.reasoning` and given back with its calls through `ChatMessage::with_reasoning`, sent as `reasoning_content` only when the server sent one, even empty (TCL-17, TCL-18); the `reasoning` field of OpenRouter and Ollama is not read. `CompletionResponse.usage`
  is the optional token count the server reports (`usage.rs`: a missing or malformed block is `None`, never estimated; `cached_tokens` is the part of the prompt served from the server's cache, read from `prompt_tokens_details.cached_tokens` or DeepSeek's `prompt_cache_hit_tokens`, 0 when absent or malformed and capped at the prompt, TOK-1 to TOK-3);
  `LlmProvider::model()` is the model a provider asks for when a request names none (empty by default): passes put it in their fingerprints. `LlmProvider::language()` is the language a provider asks the answers in (`None` by default; `retrodoc_pipeline::InLanguage` sets it, ADR 0041). `UsageProvider` + `UsageTracker` count answered calls and tokens per pass and per model (concurrency-safe; the CLI names
  the pass with `set_pass`, or `in_pass`, which closes it when the work ends). Failed attempts and internal retries are not counted.
