# Run a minimal application of each reference framework through generate

# Goal
Nothing proves today that `generate` goes through a repository of a stack the code does not know, nor through
each frequent framework. `specs/language-agnostic.md` (ADR 0036) asks for it: a minimal application per framework of
the reference set and one in a language no table knows, run by `generate` with a fake LLM, plus a check that the
prompt instructions are the same for every stack.

# Findings (code read on 2026-10-29 at 94a83b9)
* The CLI tests fake the LLM with a local chat-completions server (`crates/retrodoc-cli/tests/pass_models.rs`) that
  answers the same thing to every request: none answers per pass, so no test runs a whole `generate` through the
  binary.
* `PLAN.md` §7.4: the promotion of `source_extensions` is "not yet checked on a real repo".
* The roles prompt gives a Ruby regex as an example: one text for every stack, which LNG-4 allows.

# Approach
1. A scripted fake server: answers per pass, recognised from the request (schema name of the structured output or
   a marker of the system prompt), with the request bodies kept for the assertions.
2. An Elixir fixture (no known extension, manifest, schema nor grammar): LNG-1, LNG-2, LNG-3.
3. One fixture per framework of the reference set (one entry point, one model, one test each): LNG-9; two of them
   compared for LNG-4.
4. The fallback of each stack-specific reader (the `rails_schema` reader, the manifests, the grammars): LNG-10.

# Specs
* `specs/language-agnostic.md`: LNG-1, LNG-2, LNG-3, LNG-4, LNG-9, LNG-10; the spec is set `accepted` once
  `stack_tables_cover_the_reference_set` and `tree_sitter_reference_languages` trace the others.
